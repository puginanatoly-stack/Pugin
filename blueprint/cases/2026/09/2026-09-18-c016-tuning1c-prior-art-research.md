# Ситуация (контекст)

Продолжение той же сессии, что и C015 (архитектура моста Tuning 1C уже согласована, зафиксирована в
`Tuning 1c\Version From Clode\`). Анатолий попросил: «поищи на гитхаб подобные проекты, где
настраивается эмпирическая дисциплина AI-агентов» — открытый исследовательский запрос без указания,
сколько искать и как глубоко. Дальше последовало пять последовательных заходов поиска, каждый следующий
— по прямому отклику Анатолия на предыдущий результат, а не по заранее составленному плану.

# Мои мысли (chain of thought)

Первое решение — не делегировать поиск фоновому вееру субагентов (Research-скилл с несколькими
параллельными исследователями), хотя задача формально подходит под его триггеры («investigate, find»).
В `OPERATIONAL_RULES.md` есть прямое правило от 2026-08-27: без явного разрешения принципала — никаких
фоновых subagent'ов, весь поиск в foreground. Сделал сам, пятью точечными WebSearch-запросами плюс
WebFetch на 2-4 самых многообещающих результата за заход — не по каждой ссылке, а по тем, что реально
могли изменить ответ.

Первый заход дал шесть сопоставимых репозиториев. Попутно, не будучи целью поиска, нашёлся значимый
факт — подтверждённый, но закрытый Anthropic как «not planned» баг: хук `PreToolUse:Edit`/`Write` в
Claude Code не перехватывает запись файла через Bash. Не стал придерживать эту находку до отдельного
вопроса — вынес её сразу как отдельный риск, применимый к собственному хуку Анатолия (bsl-guard),
раз уж она обнаружилась по пути.

Для трёх диаграмм выбрал не первые три по счёту, а те, что дают наибольший контраст форм — и один выбор
сделал сам («на твой выбор»), явно назвав критерий: dsh-write-gate ближе всего по форме к bsl-guard,
значит интереснее всего для сравнения. Каждую схему строил по реальному WebFetch README проекта, не по
snippet из поиска — когда описание архитектуры расходилось между поисковым сниппетом и самим README
(например, agentlint: сниппет назвал только количество правил, README раскрыл механизм «circuit breaker
degradation»), брал за основу именно README.

Когда Анатолий сказал «академически ничего нового», не стал защищать уже сделанную работу или предлагать
разобрать те же три проекта глубже — расценил это как сигнал, что сам критерий поиска был слишком узким
(«похожий хук»), и сознательно расширил ось поиска до «структурно другая философия»: не гейт вообще
(h5i — конкуренция агентов), не после кода (Spec Kit — до кода), не то же чтение кода тем же способом
(AgentCoder — независимый дизайнер тестов). Для каждого нового проекта сразу искал точку стыковки с уже
существующими артефактами Tuning 1C (классы 7-10, классы 8/11, `data/jira/`) — не оставлял как
абстрактную «вот интересная идея».

Когда Анатолий явно назвал предпочтение (h5i) и сузил критерий (embedding, не просто cross-review), не
стал предлагать веер вариантов — сфокусировал следующий поиск конкретно под этот критерий и нашёл
AgentForge за два запроса. Важный момент дисциплины: AgentForge выглядел как идеальное совпадение, был
соблазн подать его как готовую находку — вместо этого явно проверил и написал прямым текстом, что
публичного репозитория не нашёл, это research-статья, не инструмент к установке. Ту же честность
применил и к AgentForge — при разборе двух источников retrieval (episodic memory vs live repository
index) не смешал их в одну рекомендацию, а разделил по разному времени жизни.

На финальный запрос «ищем не в гитхаб, а науку» — переключил тип источника, не тему: те же критерии
(embedding + кодовая база), но целенаправленно arXiv, не GitHub. PYTHALAB-MERA оказался ближе всего из
всего цикла — практически зеркалит структуру, которую Анатолий и TooLi@opencode вывели сами
эмпирически (память/retrieval + validation-grounded gate). Отдельно вынес находку Synapse про
деградацию плоских векторных хранилищ — не была целью поиска, но релевантна планируемой векторной
памяти в схеме 02, и промолчать о ней означало бы придержать предостережение, которое могло бы
пригодиться раньше, чем всплывёт само.

Все находки писал в один и тот же файл (`05-похожие-проекты-github.md`), наращивая его заход за
заходом, а не создавал новый файл на каждый раунд поиска — иначе история решений («что искали → что
нашли → что отклонили → куда пошли дальше») рассыпалась бы по нескольким несвязанным документам.

# Принципы и паттерны

- **Foreground-only research по явному правилу** — не делегировал фоновому вееру субагентов, хотя
  задача формально подходит под триггеры Research-скилла; сделал сам точечными WebSearch/WebFetch,
  в согласии с `OPERATIONAL_RULES.md` о токен-дисциплине.
- **Verify before present** — архитектура каждого проекта бралась из реального WebFetch README/статьи,
  не из поискового сниппета; при расхождении сниппета и первоисточника — доверие первоисточнику.
- **Честная маркировка источника** — явно различал «реальный проверенный GitHub-репозиторий» и
  «академическая работа без подтверждённого кода» (AgentForge, PYTHALAB-MERA) — ни разу не выдал
  второе за первое.
- **Точка стыковки, а не каталог** — для каждой находки формулировал конкретно, что и почему брать
  или не брать применительно к уже существующим артефактам Tuning 1C, а не оставлял как список ссылок.
- **Отзывчивый пересмотр критерия по обратной связи** — на «ничего нового» не защищал сделанное,
  расширил сам критерий поиска на следующем заходе.
- **Следование явно названному предпочтению** — после «понравился h5i» сузил поиск именно под этот
  ориентир, не продолжил широкий скан.
- **Вынесение побочных находок-рисков без запроса** — обход хука через Bash и деградация плоских
  векторных хранилищ всплыли не по цели поиска, но вынесены сразу, не придержаны до отдельного вопроса.
- **Один нарастающий журнал, не россыпь файлов** — все пять заходов писались в один и тот же
  `05-похожие-проекты-github.md`, сохраняя единую историю решений.

# Принятое решение и действие

Пять последовательных заходов поиска, каждый по прямому отклику Анатолия на предыдущий: (1) шесть
сопоставимых GitHub-проектов + находка про обход хука через Bash; (2) три DRAKON-схемы по вариациям
идеи гейта, признанные Анатолием «не новыми»; (3) три схемы по структурно другим философиям (h5i, Spec
Kit, AgentCoder), каждая с точкой стыковки; (4) AgentForge — ближайшее совпадение критерия
«h5i + embedding», честно помеченное как research без публичного кода; (5) пять академических статей
специально по запросу «не гитхаб, а наука», включая почти зеркальную архитектуру (PYTHALAB-MERA) и
академическое обоснование уже принятого решения (разбивка реестра на 3 типа). Всё записано в один
нарастающий файл с явной хронологией и явным списком отклонённого.

# Итог и ретроспектива

Открытый пункт: ни одна из внешних находок не проверена на реальном коде zup3 — это чужие заявленные
результаты и архитектуры, не перепроверенные так, как Анатолий с TooLi@opencode проверяли собственные
правила (BSL-001, C-1) на 979 модулях. Решение, что из найденного действительно применять, ещё не
принято — Анатолий читает статьи параллельно с фиксацией этого кейса.

Если пригодится снова: воспроизводимый ход — открытый исследовательский запрос без изначального плана
глубины лучше вести короткими заходами с явной точкой принятия решения между ними («что нашли → отклик
принципала → пересмотр критерия»), чем одним большим фоновым поиском на всю глубину сразу. Каждый
пересмотр критерия в этой сессии произошёл ровно потому, что был короткий заход, а не длинный —
принципал успевал сказать «не то» или «то самое, но...» после трёх находок, а не после тридцати.
