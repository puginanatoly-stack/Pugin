# Ситуация (контекст)

Продолжение той же сессии, что C015 (архитектура моста согласована) и C016 (исследование
аналогов завершено). Следующий шаг — свести всё в одну мастер-схему: форма «H» (разработчик
слева, аналитик справа, мост-облако посередине), плюс встроенный инвентарь реального состава
моста (2 MCP-сервера, 126 скилов/10 категорий — взято из файла TooLi@opencode
`список-MCP-и-скилов.md`, не выдумано). Требование по всей сессии неизменно: строгая нотация
ДРАКОН, вертикаль по умолчанию, горизонталь запрещена без явного флага-исключения.

# Мои мысли (chain of thought)

Первая попытка H-формы — mermaid `flowchart LR` снаружи + вложенные `subgraph` с `direction TB`
внутри. Анатолий вернул: «у тебя все в линию, дракон аналитиков внизу, а должен быть справа от
облака» — mermaid/dagre ненадёжно держит смешение внешнего LR и внутреннего TB. Не стал
подбирать mermaid-костыли дальше — пересобрал на CSS Grid (`.h-grid`) поверх трёх независимых,
каждая сама по себе строго вертикальных `flowchart TB`-схем. Раскладка стала делом CSS, а не
догадок dagre.

Анатолий предложил сравнить с альтернативой: «можем вместо мермейд другой формат?» → согласовали
через AskUserQuestion — сохранить mermaid-вариант как снимок для истории (`...-variant-2026-09-18.html`,
temporal-versioning) и рядом построить полностью ручной inline SVG по методике artifact-diagramming:
viewBox, currentColor-тема, свои координаты, свои маршруты петель возврата (orthogonal routing через
боковые «отводные каналы», чтобы линии не пересекались). Собрал обе версии, не выбирая за него.

Отклик: «новый вариант лучше! единственное — наложение двух блоков, сдвинь облако чуть вправо».
Не стал сразу лезть в SVG наугад — перечитал собственную координатную таблицу файла и нашёл
источник: блок «Заблокировано» (x=430-580) плюс его петля возврата (доходит до x=630) физически
залезали в блоки облака, которое начиналось с x=520. Пересчитал не только видимые прямоугольники,
но и все пять cross-column связей (retrieval/feedback), которые ссылались на старые левый/правый
края облака — сдвинул облако на +160 (520→680), колонку аналитика следом (900→1060), чтобы не
столкнуть их между собой. Заодно убрал мёртвый нулевого-размера `<rect>`, оставшийся от прошлой
правки — не потому что просили, а потому что заметил при чтении разметки.

Отдельно Анатолий предложил поискать на GitHub/вебе готовый скил или MCP, который рисует именно
в формате ДРАКОН — чтобы не рисовать вручную. Сделал точечный веб-поиск (не фоновый Research-скилл,
по стандартному правилу токен-экономии), нашёл три DRAKON-специфичных проекта (drakon_editor,
drakonhub, drakon-renderer), но ни одного, который был бы AI-вызываемым MCP/скилом — сказал об
этом прямо, не выдал desktop-редактор за замену. В этот же момент Анатолий сообщил отдельно:
«ручной инлайн красивее и эстетичнее» — не стал спорить в пользу уже вложенного труда в
mermaid+CSS-Grid вариант, просто зафиксировал предпочтение и сделал SVG-файл главным.

Финальный штрих — «добавь таблицу и опиши всё инженерным языком, красиво, и будем считать задачу
выполненной». Таблицу и её CSS/JS-фильтр не придумывал заново — вытащил дословно из уже
существующего mermaid-варианта (те же 10 категорий, те же 126 чипов-скилов), перенёс в SVG-файл
и адаптировал под его же CSS-переменные темы. Описание архитектуры написал новое — по шагам для
каждой из двух цепочек (разработчик/аналитик) и отдельно про начинку моста — инженерным языком,
без описания «что видно на картинке», а с логикой «что происходит на каждом шаге».

# Принципы и паттерны

- **Проверка по первоисточнику** — синтаксис ДРАКОН брался не по памяти, а по двум последовательным
  WebFetch (сначала википедия, затем более авторитетный drakon.tech), с явным приоритетом второго
  при расхождении.
- **Явное, задокументированное исключение вместо тихого нарушения правила** — H-форма прямо
  противоречит стандартному запрету горизонтали; зафиксировал это как осознанное исключение в
  README, а не промолчал и не отказался выполнять просьбу.
- **Инженерный язык вместо декоративной метафоры** — дважды за сессию убирал неинженерные слова
  из подписей («лапа» → «вставка», затем само слово «дракон» из заголовков узлов) по прямому
  указанию, оба раза заменяя термином из самой нотации, а не эвфемизмом.
- **Темпоральное версирование** — mermaid-вариант не редактировался и не удалялся при переходе на
  SVG, а сохранён отдельным файлом-снимком для сравнения.
- **Эмпирический пивот при исчерпании возможностей инструмента** — mermaid/dagre не потянул
  смешанный LR/TB — не подбирал обходные пути внутри того же инструмента, переключился на CSS
  Grid, а затем (по явной просьбе на сравнение) на полностью ручной SVG.
- **Диагностика по данным, а не по повторной догадке** — на расплывчатое «наложение двух блоков»
  не стал гадать по картинке, а перечитал собственную координатную таблицу и нашёл точную пару
  конфликтующих элементов до того, как менять хоть одну координату.
- **Честное «не нашёл» вместо натягивания находки** — поиск DRAKON-tooling дал три нерелевантных
  для AI-вызова проекта — сказал об этом прямо, не выдал desktop-редактор за готовое решение.
- **Следование явно названному эстетическому предпочтению** — «ручной инлайн красивее» принято
  без возражений и без попытки отстоять уже вложенный труд в альтернативный вариант.
- **Данные не изобретаются повторно** — таблица МСП/скилов при переносе в новый файл взята
  дословно из уже проверенного источника, не пересобрана из памяти.

# Принятое решение и действие

Три последовательных прохода по одному и тому же артефакту: (1) mermaid H-форма через
`LR`+вложенный `TB` → не сработала → пересборка на CSS Grid + три независимых `TB`-схемы;
(2) по явной просьбе на сравнение — параллельный ручной inline SVG-вариант той же схемы,
построенный по методике artifact-diagramming; (3) по фидбэку — точная диагностика и исправление
визуального наложения (сдвиг колонок облака/аналитика на +160, пересчёт пяти cross-column
связей, удаление мёртвой разметки), затем добавление полного инвентаря МСП/скилов (перенесён
дословно) и инженерного текстового описания обеих цепочек процесса. Финальный файл
опубликован как Artifact, синхронизирован на сетевую папку, отмечен в README как «начать
отсюда», и по отдельной просьбе сохранён копией-снимком в `Version From Clode/final/`.

# Итог и ретроспектива

Сработавший паттерн: когда фидбэк расплывчатый («наложение», без указания какого блока) — не
гадать по рендеру, а идти в собственные координаты, которые уже есть в разметке; это быстрее и
точнее, чем визуальная догадка. Второй паттерн, который стоит повторять: строить сравнение
(mermaid vs SVG) явно как два артефакта side-by-side, когда неясно заранее какой формат лучше
ляжет — вместо того чтобы спорить о формате в чате или пытаться сразу угадать предпочтение.
