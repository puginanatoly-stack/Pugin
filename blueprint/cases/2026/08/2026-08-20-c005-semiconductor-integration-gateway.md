# Ситуация (контекст)

2013, производство микросхем — небольшой, но очень инновационный проект.
Главная цель — сложные интеграции.

# Мои мысли (chain of thought)

[не надиктовано]

# Принципы и паттерны

Метод кросплатформенного шлюза для сложных интеграций между системами —
тот же принцип, что и "промежуточные модули трансформации" в C003, то
есть Anti-Corruption Layer (P04). Выбор соразмерен объёму данных на тот
момент (H001/H002 — не городить сложность сверх того, что оправдано
объёмом).

# Принятое решение и действие

Применил кросплатформенный шлюз (P04) для интеграции.

# Итог и ретроспектива

В целом решение оправдано. Ретроспективно (сейчас) Анатолий выбрал бы
Kafka. Но на момент 2013 года, при небольшом объёме данных, шлюз был
оправданным решением — шина сообщений типа Kafka была бы избыточной
сложностью для объёма задачи. Иллюстрирует H001/H002: решение должно
соответствовать объёму на момент принятия, не "лучшей практике вообще".
