# Cases — Слой 2: Решение → Рассуждение

RAG-база реальных кейсов Анатолия. Каждый кейс — одно значимое решение (инженерное или управленческое), записанное сразу после факта или по свежей памяти, с потоком рассуждений как было — не причёсанным пост-фактум.

## Структура

По годам, внутри — по месяцам (номер месяца, 2 цифры), один файл на кейс — по конвенции `Diary/`:

```
cases/
  2026/
    08/
      2026-08-20-<slug>.md
```

## Формат записи

```yaml
---
type: "DecisionCase"
id: "C001"                       # сквозная нумерация по порядку появления
domain: "Архитектура ПО"         # напр. "Архитектура ПО", "Управление командой", "Выбор стека"
tags: [architecture, 1c]        # свободные теги: architecture, team, crisis, stack-choice, code-review, hiring, ...
date: 2026-08-20
outcome: "Успех"                 # Успех | Провал | Неопределённо
emotional_state: "Спокойствие"   # состояние на момент решения — оно влияет на решение
goals: []                        # опционально: связанные TELOS-цели G0-G3
patterns: []                     # применённые принципы/паттерны проектирования
captured_via: manual             # manual | "Слепок!"
case_type: real                  # real | synthetic_illustrative — ЧТО это
status: complete                 # complete | in-progress — ЗАВЕРШЁН ли кейс (отдельная ось от case_type)
---

# Ситуация (контекст)
Сухие факты: что было известно ДО решения, какая информация была в наличии.

# Мои мысли (chain of thought)
Поток сознания — как перебирались варианты, что отбрасывалось и почему, какие компромиссы искались. Не причёсывать.

# Принципы и паттерны
Какие принципы/паттерны проектирования применили и почему именно они.

# Принятое решение и действие
Что именно было сделано.

# Итог и ретроспектива
Что понял позже. Сделал бы так же снова, или иначе?
```

Шаблон для копирования: [`_template.md`](_template.md).

**Важно:** кейсы пишет только Анатолий (сам или надиктовывает TooLi вживую) — TooLi не сочиняет кейсы за него. Это касается и иллюстративных кейсов от сторонних AI (ChatGPT и т.д.), присланных как пример формата — они НЕ реальные прецеденты и не сохраняются в эту папку как есть, даже с пометкой draft. Причина: `cases/` — это RAG-база для будущих решений агента; один выдуманный кейс внутри подрывает доверие ко всей базе. Если похожая ситуация реально была — Анатолий пересказывает её своими словами, TooLi оформляет по шаблону.

## Кодовое слово «Слепок!»

Исключение из правила выше. Когда в ходе совместной работы над задачей Анатолий говорит **«Слепок!»**, это значит: только что решённую задачу мы делали правильно — с осознанным применением принципов/паттернов проектирования — и её стоит зафиксировать как кейс.

**Порядок действий TooLi:**
1. Синтезировать кейс из реального диалога сессии (не выдумывать — только то, что реально обсуждалось и решалось).
2. Явно назвать применённые принципы/паттерны в разделе «Принципы и паттерны».
3. Показать черновик в чате, `captured_via: "Слепок!"` в frontmatter.
4. Сохранить файл в `cases/<год>/<месяц>/` только после явного подтверждения Анатолия — не раньше.
