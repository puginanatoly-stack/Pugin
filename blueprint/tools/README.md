# Tools

Два скрипта, одна лёгкая зависимость (`pyyaml`).

## Установка

```bash
pip install -r tools/requirements.txt          # только для запуска
pip install -r tools/requirements-dev.txt       # + pytest, для тестов
```

## `build_context.py`

Собирает весь слепок (`PERSONALITY_MODEL.yaml`, `cases/`, `lenses/`,
`training_data/pairs/`, **`GUIDE_FOR_FINE_TUNING.md` + `OPEN_QUESTIONS.md`**)
в артефакты в корне проекта:

- `context.md` — единый markdown (полная версия, ~107 КБ), готов к вставке
  в system prompt/контекст любого агента.
- `context.compact.md` — то же самое, но без тел кейсов и синтетических пар
  (`--compact`, ~46 КБ) — только модель принятия решений: ценности,
  эвристики, паттерны, agent guide. Кейсы/пары достаются точечно через
  `rag_query.py`.
- `context.json` — плоский список типизированных чанков (id, type, status,
  title, text, source_file) для программного использования (RAG).

```bash
python tools/build_context.py            # полный context.md
python tools/build_context.py --compact  # context.compact.md
```

**Валидация — падает громко, а не молча.** Перед записью файлов скрипт
проверяет: все ожидаемые top-level ключи `PERSONALITY_MODEL.yaml` на
месте (защита от повторения инцидента с потерянным `perception_filters:`
из CHANGELOG.md), у каждого кейса есть обязательные поля frontmatter
(`id`/`domain`/`date`/`outcome`), и regex `PAIR_RE` реально распарсил
все пары в `training_data/pairs/*.md` (если формат пары изменится, а
regex — нет, скрипт упадёт с понятной ошибкой вместо того, чтобы тихо
потерять пары).

Слой 4 (`GUIDE_FOR_FINE_TUNING.md` + `OPEN_QUESTIONS.md`) теперь реально
попадает в контекст — раньше файл только объявлялся константой, но не
читался, и агент получал модель решений без протокола её коррекции.

Безопасно перезапускать в любой момент — только читает файлы слепка,
ничего в них не пишет. Перегенерировать (`--compact` тоже) после любого
обновления `PERSONALITY_MODEL.yaml`/кейсов/линз/пар — CI проверяет
свежесть автоматически (см. `.github/workflows/blueprint-ci.yml`).

## `rag_query.py`

RAG-lite поиск по контексту: чистый Python TF-IDF + косинусное сходство,
пересчитывается на лету при каждом запросе (корпус маленький — миллисекунды).
Без персистентного индекса, без pickle.

```bash
python tools/rag_query.py "автоматизировать сейчас или потом"
python tools/rag_query.py "canary deployment" --top-k 3
python tools/rag_query.py "TDD" --type heuristic,pattern
python tools/rag_query.py "риск" --min-score 0.05
python tools/rag_query.py "риск" --json          # машиночитаемый вывод
python tools/rag_query.py "что-то" --rebuild      # форсировать пересборку context.json
```

**Лёгкий стемминг.** Токены длиннее 5 символов обрезаются до первых 5
(«деплой»/«деплои»/«деплою» → «депло», «автоматизация»/«автоматизировать»
→ «автом»). Не настоящая морфология (pymorphy2 — реальная зависимость,
которую сознательно не тянем ради корпуса на ~150 чанков, см. H001/H002
в самом слепке), но закрывает главные случаи для русского поиска. Если
качества не хватит — см. `ROADMAP.md`.

**Вес по статусу.** `confirmed`/`complete` = 1.0, `in-progress` = 0.9,
`ambivalent` = 0.7, `draft` = 0.5, **`rejected` = 0.15** и явный флаг
`⚠ REJECTED` в выводе (`do_not_follow: true` в `--json`). Запрос про
YAGNI не должен возвращать P01 (rejected) как будто это совет — паттерн
всё ещё находится по лексическому сходству, но помечен и задвинут вниз.

Если `context.json` ещё нет — соберёт его сам перед поиском.

Совет: слепок отвечает на вопросы, которые ему задали. Попробуй спросить
инструмент о том, чего в этом проекте нет.

## Тесты

```bash
python -m pytest tools/tests/ -v
```

13 тестов: идемпотентность сборки, число чанков-эвристик = число записей
в YAML, у каждого кейса обязательные поля, уникальность id
perception_filters, regex пар матчит все элементы, потеря top-level ключа
YAML валится с понятной ошибкой, `--compact` реально меньше и без кейсов,
известные запросы («Парето» → H001, «canary» → P12) находят ожидаемые id,
rejected-чанк помечен и имеет пониженный вес.

Тесты идут против **реальных данных слепка**, не фикстур — корпус
маленький и однопользовательский, «тестовые данные» и есть продакшен.

## CI

`.github/workflows/blueprint-ci.yml` (в корне репозитория, не здесь) —
на каждый push/PL, затрагивающий `blueprint/`: ставит зависимости,
гоняет тесты, пересобирает `context.md`/`context.compact.md`/`context.json`
и падает, если пересобранное отличается от закоммиченного (`git diff
--exit-code`). Это делает «контекст свежий» машинно-проверяемым
инвариантом.

## Почему не полноценная vector DB

Корпус сейчас — 8 кейсов, 25 эвристик, 52 синтетические пары, 112 чанков
итого. Полноценная vector DB (Pinecone/Qdrant/Chroma) с embedding-моделью
для такого объёма — избыточная сложность (см. H001/H002/N+1 Rule в
`PERSONALITY_MODEL.yaml`). Когда корпус вырастет на порядки — тогда и
есть смысл пересмотреть подход, не раньше (см. `ROADMAP.md`).
