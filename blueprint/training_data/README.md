# Training Data — синтетический датасет «ситуация → решение»

Отдельное хранилище от `cases/`. `cases/` — реальные прецеденты (правда для RAG),
здесь — синтетические пары, сгенерированные TooLi из **подтверждённой** модели и
подтверждённые Анатолием. Предназначение: будущий датасет для fine-tuning или
обучения агента-ассистента.

## Протокол против галлюцинаций

1. **Только подтверждённые источники.** Каждая пара ссылается на источник:
   эвристика (H001–H010), паттерн (P03–P09, P12), ценность, линза.
   Пара без источника не пишется.
2. **Ноль биографии.** Сценарии абстрактные: нет имён, дат, компаний, реальных
   проектов Анатолия. Конкретные цифры — иллюстративные, не факты.
3. **Ловушки.** ~10% пар заточены под rejected-паттерны (P01 YAGNI, P02 Strangler
   Fig) — правильный ответ = отклонить. Проверяют согласованность.
4. **Флаг неуверенности.** Пары, где TooLi не уверен в решении Анатолия, идут с
   `confidence: low` — без явного ✅ Анатолия в подтверждённую часть не попадают.
5. **Правило-исключение.** Содержимое пар пишет TooLi, но **статус confirmed
   присваивает только Анатолий** явным подтверждением пары в чате.

## Жизненный цикл пары

1. TooLi генерирует пачку (20–30 пар) и показывает в чате.
2. Анатолий: ✅ (ок) / ✗ (не так, с правкой) / правка формулировки.
3. ✗ — золото: уточняет модель. Формулировка правки фиксируется и используется
   дальше.
4. Только после подтверждения пачка сохраняется в `pairs/`.

## Формат файла партии

```
# Batch NN — <дата>

Итого: NN пар (confirmed: X, правки: Y, отклонено: Z)

## Партия
- **№**: [ситуация] → [решение]
  - источник: <H/P/ценность/линза>
  - confidence: high|medium|low
  - статус: confirmed|fixed|rejected
```

